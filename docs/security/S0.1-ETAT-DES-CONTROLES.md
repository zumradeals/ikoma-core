## Exceptions et masquages examinés

- `.gitleaksignore` contient deux empreintes historiques exactes de constantes de tests (`PosteTest.php`, `InstallationTest.php`), expliquées dans `docs/REVUE_SECURITE.md`. Le diagnostic ne repubie aucune valeur de jeton. Aucune découverte nouvelle dans les rapports.
- Gate ZAP : `10010` faible pour XSRF-TOKEN précis, `10109` information pour module JS racine, `10112` information pour deux noms de cookies, `10049-1` information pour absence de cache à la racine/sitemap, `10049-3` information pour ressources statiques publiques. Les rapports restent visibles ; ce ne sont pas cinq vulnérabilités CVE acceptées en production.
- CSP `style-src-attr 'unsafe-inline'` : exception de conception déjà documentée dans la revue, pas une nouvelle décision S0.1. Ne pas en déduire une ouverture de `script-src`.
- `--ignore-severity=low/medium` de Composer et `--audit-level=high` de npm sont des exclusions de seuil explicites. La revue L11 historique n'est pas une dispense permanente de traitement.
- `|| true` du scan production neutralise un contrôle de sécurité. Les `|| true` du nettoyage Compose, chown, lecture optionnelle et affichage `docker image ls` ont d'autres rôles : ils ne sont pas tous des preuves de scanner désactivé.

## Publication des artefacts et erreurs techniques

Le workflow publie `analyses-securite` avant l'étape d'expurgation. Le script `redact-test-artifacts.py` ne traite que `test-results`, puis publie `captures-l3`. Les comptes des runs sont fictifs, mais des rapports HTTP peuvent contenir des en-têtes de session de recette : vérifier leur neutralisation avant toute diffusion élargie. Aucune fuite de secret de production n'est établie par ce constat. Les résumés versionnés S0.1 omettent les valeurs de cookies et les journaux d'installation.

Les erreurs réseau/base scanner ne doivent pas devenir un succès ; le job production ne distingue actuellement pas ce cas. Le `set +e` de l'audit dépendances permet de collecter les deux retours, qui sont ensuite vérifiés ; ce n'est pas équivalent à `|| true`. Une analyse partielle ou un artefact absent doit être visible, même si d'autres tests réussissent.

Les propositions de ce tableau sont soumises à S0.2 ou à un lot ultérieur après validation ; aucune nouvelle règle n'est imposée par ce document.
