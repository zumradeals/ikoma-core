# S0.2 — Résultats vérifiés de la qualification expérimentale C1–C2

**Date : 31 octobre 2026. État : deux analyses expérimentales réussies, aucune correction intégrée au produit livré.**

## 1. Sources de preuves et méthode

Dépôt `zumradeals/ikoma-core`, base `main` `83fd2f550f7f9aaba95fcea6195e6b1f426081c4` (après R06). Branche d'essai : `security/s0-2-critical-qualification`, PR #47, **non fusionnée**.

CI expérimentale [41227034052](https://github.com/zumradeals/ikoma-core/actions/runs/41227034052), deux jobs **réussis** :
- [qualification-libxml2-alpine, artefact 13051914722](https://github.com/zumradeals/ikoma-core/actions/runs/41227034052/artifacts/13051914722)
- [qualification-gosu-go, artefact 13052580218](https://github.com/zumradeals/ikoma-core/actions/runs/41227034052/artifacts/13052580218)

Les deux archives ont été téléchargées et leurs résumés JSON inspectés. Le scanner Trivy analyse les paquets de toutes gravités sur les **IDs des images candidates** et conserve les constats dans son rapport temporaire ; l'artefact publie uniquement l'identité, les comptages et les constats critiques/élevés, sans `docker inspect` ni variable d'environnement. Les bases/rapports doivent être renouvelés en cas de changement d'avis ou de digest ; ces sorties ne sont pas reproductibles à l'octet sur des tags mobiles.

Le premier essai avait échoué au contrôle de restauration parce que la table fictive existait encore ; le protocole a été corrigé avec `pg_restore --clean --if-exists`. Un autre échec portait sur le décodage du flux JSON multi-objets de govulncheck, corrigé avant l'exécution finale. **Ces échecs de qualification ne sont pas des vulnérabilités IKOMA ; ils n'ont pas été masqués.**

## 2. C1 — CVE-2026-6653 libxml2

**Candidat officiel expérimental :** `php:8.5.12-fpm-alpine3.24` et `postgres:18.6-alpine3.24`. Les deux images candidates ont reçu les mises à jour publiées dans les dépôts officiels Alpine 3.24 via `apk upgrade --no-cache`, **sans mélanger de distribution**. Le code IKOMA n'est pas copié dans le runtime PHP de cet essai, et la base PostgreSQL est neuve et fictive.

| Candidat après mises à jour | Image ID SHA-256 (configuration Docker) | Trivy HIGH | Trivy CRITICAL | CVE-2026-6653 |
|---|---|---:|---:|---|
| PHP 8.5.12 Alpine | `665b2a549d0a287b0ab9d48f6f05221dc4dbe18f360e5069ad0996edf92157ed` | **0** | **0** | absente du rapport |
| PostgreSQL 18.6 Alpine | `151711e6d837e9936701409592bded911ce89db4deb78d85bd59a7e13c22d79d` | **25** | **1** | absente du rapport |

PHP compilée et chargée : **libxml2 2.13.9**. Six extensions requises vérifiées (pdo_pgsql, mbstring, ZIP, XMLReader, GD, libxml). Tests fictifs CSV, XML (valide/invalide), ZIP et GD/JPEG **réussis**. PostgreSQL 18.6 Alpine : service lancé en réseau isolé ; création SQL, sauvegarde et restauration fictives **réussies**, sans base client ni migration de volume existant.

**Nouvelle CVE rencontrée et éliminée dans le candidat :** les premiers scans Alpine avaient trouvé `CVE-2026-111497` (brotli-libs 1.2.0-r1) dans PHP et PostgreSQL et `CVE-2026-92392` (curl/libcurl 8.22.0-r0) en HIGH. Les mises à jour officielles Alpine ont éliminé ces alertes selon le second scan ; la première est corrigée par Brotli 1.2.1-r0 publié dans Alpine 3.24. Aucune liste d'ignorance ni changement de seuil.

**Attention :** l'absence de `CVE-2026-6653` dans ces candidates ne prouve pas que la distribution puisse être changée en production sans risque. Pas encore de recette complète du code IKOMA ni de qualification des locales/collations, des extensions PostgreSQL, de la compatibilité des index/trigrammes/unaccent, de l'import OpenSpout, des rôles, des badges et des E2E sur un déploiement intégré Alpine.

## 3. C2 — CVE-2025-68121 / GO-2026-4337 sur gosu

Image officielle **inchangée** `postgres:18.6-trixie` ; extraction du binaire réel `/usr/local/bin/gosu`.

- SHA-256 mesuré et comparé à R04 : `52c8749d0142edd234e9d6bd5237dff2d81e71f43537e2f4f66f75dd4b243dd0`.
- Analyse `govulncheck v1.1.4`, `scan_mode=binary`, `scan_level=symbol`.
- Avis officiel GO-2026-4337 vérifié (alias CVE-2025-68121).
- **Un finding associé à l'avis, zéro symbole vulnérable signalé.**
- Aucune exclusion globale appliquée. Les 25 autres alertes Go `stdlib` du candidat PostgreSQL doivent être qualifiées individuellement si l'image doit être homologuée.
- Le même utilitaire `gosu` et son code Go 1.24.6 restent présents dans l'image PostgreSQL Alpine ; **Trivy y détecte toujours une CVE critique**. Il serait faux d'annoncer une image PostgreSQL « zéro critique » au seul motif de l'analyse de symboles.

Verdict proposé : **non-atteignabilité au niveau des symboles pour cette CVE précise sur ce binaire précis**. Une décision de non-applicabilité officielle requiert une validation responsable et une révision à chaque changement du SHA-256. Ne pas désactiver le scanner ni supprimer le constat historique.

## 4. Décision architecturale requise avant adoption

Ces observations constituent un **GO pour étudier un prototype intégré et isolé**, pas un GO de production. Pour basculer les images IKOMA vers une autre base, il faut une autorisation distincte et un contrat de compatibilité comprenant :
1. construire les images finales réellement distribuables et les trois services identifiés par digest, conserver Trivy bloquant ;
2. valider migrations sur base **fictive**, import OpenSpout CSV/XLSX, authentification, rôles/permissions, badges, contrôle des accès, journaux, synchronisation et tests E2E ;
3. comparer PostgreSQL 18.6 `glibc` contre `musl`, locales/collations, normalisation et indexes, ainsi que sauvegarde/restauration de recette et plan de retour arrière ;
4. auditer les **25 HIGH Go et l'alerte CRITICAL gosu** avec le même standard de preuve, sans les rendre invisibles ;
5. vérifier les règles de livraison et conserver versions, digests et rapports complets de la configuration retenue.

**État actuel** : `main` reste sur Debian Trixie, avec le dispositif Trivy bloquant et les deux critiques historiques non corrigées. La PR #47 ne doit pas être fusionnée en l'état ; gel des nouvelles mises en service commerciales avec données réelles maintenu.
