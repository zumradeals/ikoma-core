# S0.5 — Candidat PostgreSQL transportable et qualification indépendante

**Statut : laboratoire uniquement. Aucun déploiement, aucune migration, aucune publication de registre ni fusion autorisés par ce dossier.**

## Vision — pourquoi

Une construction CI verte ne signifie pas qu'une image transportée sera identique à celle analysée, ni qu'une équipe saura la retrouver après expiration des artefacts. Le présent lot produit une **archive transportable à durée de conservation limitée**, réimportée par un runner indépendant. Il **ne crée pas** de version de production durable.

## Conception — contrats explicites

1. **Source de vérité : Git.** La PR #54 S0.4 fixe les parents `golang@sha256:...`, `postgres@sha256:...`, la source `gosu` officielle et l'empreinte attendue du binaire dans `docs/security/S0.4-IMAGE-LOCK.json`. Cette PR S0.5 **dépend de la branche de #54** ; elle ne doit pas être fusionnée indépendamment et doit être requalifiée après tout changement du verrou parent.
2. **Transport intègre :** construire l'image corrigée dans un runner isolé ; scanner l'image **avant** export ; exporter une unique image `ikoma-s05:rc` par `docker save`. L'archive porte un SHA-256 complet, le digest de la configuration embarquée **et séparément** l'identifiant de l'image source tel que renvoyé par Docker (éventuellement celui d'un index OCI). Ces deux empreintes peuvent différer sans être interchangeables ; le manifeste décrit exactement la provenance autorisée, le commit Git testé, les parents et l'empreinte `gosu`.
3. **Importation indépendante :** un autre job sur un runner neuf télécharge l'archive par GitHub Actions, compare son SHA-256, importe par `docker load`, confronte l'ID de l'image importée aux identités source/configuration **distinctement attestées** dans le manifeste, extrait le `gosu`, vérifie son SHA-256 et la révision Git officielle. Le scanner Trivy s'exécute à nouveau sur **cet ID importé** ; seuil zéro HIGH/CRITICAL, absence de règle d'ignorance.
4. **Vérification fonctionnelle sans données client :** démarrer PostgreSQL uniquement sur un volume temporaire jetable et un réseau désactivé ; insérer le jeu S0.3-B de **1 000 visiteurs, 1 000 badges et 2 000 passages** et vérifier leur effectif. Détruire le conteneur après la CI.
5. **STOP automatique :** hash modifié, doublon/chemin dangereux d'archive, contenu d'image ambigu, origine `gosu` non conforme, ID différent après import, scan incomplet ou non nul, PostgreSQL incapable de démarrer, effectifs incorrects. Les tests de refus doivent continuer de passer.
6. **Preuves séparées :** artefact archive plus manifeste et rapport de qualification **sans données personnelles**. Les rapports Trivy bruts restent en environnement de CI. La commande `docker save` n'est pas un mécanisme de signature ni de distribution commerciale.

## Limites de vérité importantes

- Le SHA-256 de l'archive `.tar` **n'est pas** le digest d'un manifeste de registre OCI. L'ID `sha256:...` de l'image Docker est l'empreinte de sa configuration ; il **n'est pas interchangeable** avec un digest de manifeste publié dans un registre.
- Les archives GitHub Actions ont une **rétention temporaire**, ici 30 jours. Elles ne sont pas une source de vérité pérenne ni une solution de distribution opérationnelle.
- Le prochain lot devra qualifier une **publication immuable** dans un registre explicitement autorisé, par digest de manifeste, avec contrôle d'accès, signature/attestation et vérification par le consommateur sur l'image effectivement distribuée. **Aucun accès à un registre n'est utilisé dans S0.5.**
- Les vérifications synthétiques ne remplacent pas une reprise sur une copie réelle représentative et autorisée. Le retour automatique de code ne restaure pas les transactions d'une base migrée.

## Contrat de décision opérationnelle

Les noms des responsables maintenance, sécurité et exploitation, leurs délais de réponse, la périodicité des mises à jour, la fenêtre de bascule, le RPO/RTO, une copie représentative autorisée et un plan documenté de réconciliation des écritures restent **à décider et à signer**. Aucun nom, SLA ou autorisation de transfert n'est inventé.

**Décision de ce lot : GO de qualification du transport temporaire uniquement. NO GO fusion automatique, publication de registre, modification de `docker-compose.prod.yml`, migration de données, déploiement réel ou commercialisation.**
