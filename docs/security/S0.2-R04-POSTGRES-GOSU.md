# R04 — PostgreSQL et gosu : mesure du binaire officiel et absence de candidat corrigé qualifié

Base : `ace54da1a8a93855c7c246b7d1b1a22fcd2a5a8f`. Date : 31 octobre 2026. Statut : **recherche et qualification ; aucun remplacement d'image adopté sans candidat corrigé compatible démontré**.

## Sources officielles et choix non exécutés

Le [manifeste official-images PostgreSQL](https://github.com/docker-library/official-images/blob/master/library/postgres) relie `18.6-trixie` au commit source `e00e1bd34ec5c8a8e7ad89b273b3d42efaf6d5bc`. Son [Dockerfile immuable](https://github.com/docker-library/postgres/blob/e00e1bd34ec5c8a8e7ad89b273b3d42efaf6d5bc/18/trixie/Dockerfile) utilise gosu 1.19 et PostgreSQL `18.6-1.pgdg13+2`. La [publication gosu 1.20](https://github.com/tianon/gosu/releases/tag/1.20), dernière publication examinée, annonce encore une construction avec Go 1.24.6. Changer le seul numéro gosu vers 1.20 ne démontre donc pas la suppression des 26 alertes stdlib Go du rapport de référence.

La [politique officielle gosu](https://github.com/tianon/gosu/blob/1.20/SECURITY.md) explique que les interfaces Go non appelées ne justifient pas systématiquement une reconstruction, et propose une analyse d'atteignabilité. C'est une position de l'éditeur, **pas une preuve individuelle sur les 26 CVE du binaire utilisé par IKOMA**. Aucun verdict global faux positif, aucune exclusion scanner ni risque accepté n'est ajouté. Les symboles liés et chemins nécessaires à une exception restent à démontrer avec une analyse dédiée.

Les variantes officielles Alpine et Bookworm existent ; elles changeraient la distribution, les bibliothèques et potentiellement les locales/collations. Leur adoption n'est pas déduite de la seule existence d'un tag. PostgreSQL 19 est une autre version majeure et n'est pas retenu. Un gosu recompilé en interne ou un binaire remplacé à la main constituerait un nouvel artefact à maintenir : aucune solution de ce type n'est introduite.

Conclusion de recherche : aucun artefact officiel maintenu, compatible avec le contrat courant et démontré corrigé pour les alertes stdlib n'a été qualifié. L'image actuelle est mesurée et testée ; elle n'est pas rebaptisée « corrigée ». Une nouvelle décision sera nécessaire pour qualifier une autre base ou cadrer l'analyse d'atteignabilité, sans désactiver Trivy.

## Tests sur données fictives

`scripts/security/postgres-runtime-probe.py` refuse l'exécution hors GitHub Actions. Après l'installation et la recette production existantes, elle teste les opérations SELECT/INSERT/UPDATE/DELETE sous `ikoma_app` dans une table temporaire, transaction intégralement annulée. Elle contrôle les permissions d'audit SELECT/INSERT et l'absence d'UPDATE/DELETE/TRUNCATE, ainsi que le rôle applicatif non superutilisateur. Aucun nom de visiteur, secret ni contenu métier n'est extrait.

L'étape précédente `deploy/prod/ci-recette.sh` vérifie démarrage, mise à jour/retour arrière, sauvegarde chiffrée et restauration dans une base fictive vierge, avec audit et effectifs identiques. La sonde n'affirme pas avoir réalisé elle-même cette restauration. Toute mesure ou vérification SQL manquante bloque son étape. Les preuves sont publiées dans `r04-runtime`, complétées par `analyses-images-finales` et les journaux de recette.
