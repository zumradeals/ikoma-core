# IKOMA ACCESS — S0.2 / implémentation du tri portable

**Décision :** le 31 octobre 2026, le responsable a autorisé l'implémentation immédiate et les tests directs sur l'application en construction. La voie retenue est `COLLATE "C"` pour les classements de visiteurs. Les différences d'affichage avec l'ancien tri Debian sont acceptées en environnement de développement.

## Contrat fonctionnel

- Filtrage inchangé : événement courant, visiteurs non retirés, recherche accent-insensible, correspondance multi-mots et trigrammes.
- Classement des résultats de recherche inchangé jusqu'aux départages : qualité arrondie décroissante, priorité VIP décroissante, score fin décroissant ; départage désormais `full_name COLLATE "C" ASC`, puis UUID ascendant.
- Liste sans recherche : `full_name COLLATE "C" ASC`, puis UUID ascendant, y compris les pages de l'administration, l'accueil, les groupes, l'hôte et la sélection de badges.
- Recherche locale : comparaison par point de code Unicode, compatible avec l'ordre UTF-8 binaire PostgreSQL `C`, et non par unité UTF-16 JavaScript.
- Aucun changement du comportement d'attribution d'identité, de badge, d'autorisation ou de journal d'audit.

## Implémentation

- SQL applicatif : `VisitorSearch`, `AdminVisitorsController`, `GroupesController`, `HostController`, `BadgeWorkshopController`.
- Hors-ligne : `resources/js/poste/local/search.ts`.
- Index non destructif : `visitors_active_name_c_idx` sur `(event_id, full_name COLLATE "C", id)` pour les visiteurs actifs. Migration réversible, aucune réécriture de donnée.
- Tests : jeu fictif d'accents, casse, priorité VIP, UUID, Unicode hors BMP et comparaison Debian/Alpine ; E2E navigateur diagnostic au premier échec, puis suite complète à faire réussir.

## Critères de vérification

1. `make test` et `make test-front` réussissent sur base fictive.
2. Les résultats et leurs ordres explicites correspondent entre PostgreSQL Debian et Alpine. L'ordre historique implicite reste documenté et ne constitue pas une assertion de parité.
3. Les E2E accueil/agent doivent être réparés et rejoués sur le code final. L'analyse Go/gosu reste indépendante des tests fonctionnels.
4. Ne pas confondre réussite d'essais sur données fictives avec garantie de sécurité générale.

## Retour arrière

Pour revenir au tri précédent, revert du commit applicatif et de la migration avec son `down()`, après contrôle de l'état de la branche. Les données des visiteurs ne sont pas converties par cette opération. Ne jamais réutiliser un répertoire de données PostgreSQL entre distributions : une bascule de distribution exige une sauvegarde et une restauration sur une base neuve.
