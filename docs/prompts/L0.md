# PROMPT L0 — Fondations du dépôt

> Projet de travail. À coller tel quel dans ChatGPT Work, après validation du lot précédent.

CONTEXTE
Dépôt GitHub : ikoma-accueil. Produit : système de vérification rapide des visiteurs pour site sensible (badges QR, poste d'accueil sur tablette, pilotage mobile). Le dépôt contient déjà AGENTS.md, README.md et le dossier docs/ (plan de conception, journal des décisions, prompts, prototype de démonstration). Lis AGENTS.md puis docs/PLAN_CONCEPTION.md avant de commencer.

OBJECTIF
Mettre en place les fondations reproductibles du projet, sans aucune fonctionnalité métier.

À FAIRE
1. Vérifie que AGENTS.md, README.md, docs/PLAN_CONCEPTION.md et docs/JOURNAL_DECISIONS.md existent. Ne les modifie pas, sauf pour compléter le README.
2. Vérifie les versions stables actuelles puis installe à la racine, SANS écraser les fichiers existants (si l'installeur exige un dossier vide, installe dans un dossier temporaire puis déplace) : PHP (>= 8.3), Laravel, Inertia.js avec Vue 3 et TypeScript (le kit de démarrage Laravel Vue/Inertia est accepté s'il est compatible avec les règles d'AGENTS.md), Tailwind CSS, Vite. Base PostgreSQL. N'installe pas Livewire.
3. Fournis un docker-compose.yml (Nginx, PHP-FPM, PostgreSQL, build front) pour lancer le projet avec une seule commande, et un Makefile avec : install, up, down, test, test-front, e2e, lint, migrate-fresh-seed.
4. Active les extensions PostgreSQL pg_trgm et unaccent par migration.
5. Ajoute Laravel Pint, Larastan (niveau raisonnable), Pest, ESLint, vue-tsc, Vitest et Playwright, et une CI GitHub Actions qui lance lint + analyse + tests à chaque pull request.
6. Crée une mise en page de base (layout Vue) avec le design system de la section 8 du plan : couleurs, typographie, composants Vue bouton / carte / étiquette de catégorie / bandeau d'état, en variables Tailwind. Documente-les dans docs/design-system.md. Page d'accueil provisoire « IKOMA Accueil — en construction ».
7. Prépare la PWA : manifeste, service worker (vite-plugin-pwa), icône provisoire, sans logique métier. La page provisoire doit s'ouvrir sans réseau après une première visite.
8. Complète README.md en français pour un non technicien (à la suite du contenu existant) : comment lancer le projet en 3 commandes, comment lancer les tests.

CONTRAINTES
- Aucun fichier .env commité. Fournis un .env.example minimal (clé de l'application et accès base de données uniquement).
- Aucune fonctionnalité métier ni table métier pour l'instant.
- Ne supprime ni n'écrase AGENTS.md, README.md ni le dossier docs/.
- Tout en français pour la documentation et l'interface.

CRITÈRES D'ACCEPTATION
- Sur une machine propre : clone + les commandes du README = site visible dans le navigateur.
- make test et make lint passent. La CI est verte.
- Le layout est conforme aux couleurs et aux principes du plan.
- Un test Playwright prouve que la page provisoire s'ouvre hors ligne après une première visite.

LIVRABLE
Une pull request « L0: fondations » + un rapport (fait / pas fait / commandes de vérification / questions).
