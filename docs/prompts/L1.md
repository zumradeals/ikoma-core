# PROMPT L1 — Comptes, rôles, 2FA, journal d'audit

> Projet de travail. À coller tel quel dans ChatGPT Work, après validation du lot précédent.

CONTEXTE
Le lot L0 est validé et fusionné. Lis AGENTS.md et docs/PLAN_CONCEPTION.md (sections 2, 5, 6, 9).

OBJECTIF
Mettre en place l'authentification renforcée, les rôles et le journal d'audit non modifiable.

À FAIRE
1. Authentification avec Laravel Fortify : connexion, déconnexion, mot de passe robuste, double authentification TOTP (obligatoire pour les rôles superviseur et administrateur), déconnexion automatique après inactivité (durée réglable dans la table settings).
2. Pas d'inscription publique : les comptes sont créés uniquement par un administrateur.
3. Rôles et droits avec spatie/laravel-permission : administrateur, superviseur, agent_accueil, hote, encadreur. Matrice de droits conforme à la section 2 du document de fonctionnement (tableau « Acteurs et rôles »).
4. Écran Administration > Comptes (Vue + Inertia) : créer, désactiver, réinitialiser le mot de passe, attribuer un rôle. Simple, gros boutons, aide courte.
5. Journal d'audit : table audit_logs en insertion seule (le compte de la base utilisé par l'application n'a pas le droit UPDATE/DELETE sur cette table), chaque ligne contient l'empreinte de la précédente (chaînage). Journalise : connexion, échec de connexion, création/désactivation de compte, changement de rôle.
6. Commande artisan audit:verify qui contrôle l'intégrité de la chaîne et signale toute rupture.
7. Écran Administration > Journal : liste filtrable (acteur, action, date), lecture seule.
8. Données fictives : un compte par rôle (mots de passe jamais commités ; génération au seed avec affichage unique en console).

CONTRAINTES
- Aucun autre module métier. Pas de tables visiteurs/badges.
- Contrôle d'autorisation côté serveur sur chaque route et chaque contrôleur.
- Limitation de débit sur la connexion.

CRITÈRES D'ACCEPTATION
- Tests Pest : un agent_accueil ne peut pas ouvrir l'administration ; un superviseur sans 2FA est forcé de l'activer ; 5 échecs de connexion déclenchent le blocage temporaire ; toute modification manuelle d'une ligne d'audit est détectée par audit:verify.
- Tentatives non autorisées journalisées.
- make test, make lint, CI verts.
